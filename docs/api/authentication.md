# Authentication API

PeakCloud uses server-side session authentication.

The browser receives an opaque session token through an HttpOnly cookie. Only a SHA-256 hash of the session token is persisted in PostgreSQL.

Passwords are hashed using Argon2id before they are stored.

## Base URL

Development:

```text
http://localhost:8080
```

## Register

Creates a new PeakCloud account and authenticated session.

### Endpoint

```http
POST /api/v1/auth/register
```

### Request

```json
{
  "email": "user@example.com",
  "display_name": "Example User",
  "password": "a-password-with-at-least-12-characters"
}
```

### Success

```text
201 Created
```

The response contains the created user and sets the PeakCloud session cookie.

### Errors

```text
400 Bad Request
409 Conflict
500 Internal Server Error
```

A `409 Conflict` is returned when an account with the supplied email already exists.

---

## Login

Authenticates an existing PeakCloud account.

### Endpoint

```http
POST /api/v1/auth/login
```

### Request

```json
{
  "email": "user@example.com",
  "password": "a-password-with-at-least-12-characters"
}
```

### Success

```text
200 OK
```

A successful login creates a new server-side session and sets the session cookie.

### Errors

```text
400 Bad Request
401 Unauthorized
500 Internal Server Error
```

---

## Current User

Returns the currently authenticated user.

### Endpoint

```http
GET /api/v1/me
```

### Success

```text
200 OK
```

Example response:

```json
{
  "user": {
    "id": "9376c480-e0dd-4d54-8d73-f0cf02876309",
    "email": "user@example.com",
    "display_name": "Example User",
    "created_at": "2026-08-09T21:45:28-07:00",
    "updated_at": "2026-08-09T21:45:28-07:00"
  }
}
```

### Unauthenticated

```text
401 Unauthorized
```

---

## Logout

Invalidates the current server-side session and clears the browser session cookie.

### Endpoint

```http
POST /api/v1/auth/logout
```

### Success

```text
204 No Content
```

---

## Session Security

PeakCloud sessions use the following security model:

- Session tokens are generated by the backend.
- The raw session token is sent only to the client.
- The browser stores the token in an HttpOnly cookie.
- PostgreSQL stores only a SHA-256 hash of the token.
- Session tokens have an expiration time.
- Logout invalidates the server-side session.
- Expired or invalid sessions cannot access protected endpoints.
- The session cookie uses SameSite=Lax.
- Secure cookies can be enabled for production deployments.

## Password Security

PeakCloud never stores plaintext passwords.

Passwords are hashed using Argon2id before being persisted in PostgreSQL. Authentication compares the supplied password against the stored Argon2id hash.

## Protected Routes

Endpoints that require authentication return:

```text
401 Unauthorized
```

when a valid PeakCloud session is not present.

The web application also prevents unauthenticated users from accessing protected workspace pages.
